# TDnet「悪材料に見える開示」イベントスタディ

撤退・閉店・減損などの「悪材料に見える開示」の後、利益改善がまだ株価に織り込まれていない小型株を拾えるかを検証する。
過去データでエッジが確認できた場合だけ、毎日の自動スキャナー（Phase 3）にする。

| Phase | 内容 | 状態 |
|---|---|---|
| 1 | キーワード開示のイベントスタディ（20/60/120/250営業日後の TOPIX 比超過リターン） | エンジン完成・テスト済み。**実データ待ち** |
| 2 | 減益・赤字の決算短信を追加、開示時点の割安度（時価総額÷会社予想営業利益など）で絞り込み | 未着手 |
| 3 | 毎営業日20時のスキャン → AI 要約・利益影響額の試算 → 監視リスト・通知 | Phase 1・2 で優位性が出た場合のみ |

## 必要なデータ

| データ | 用途 | 入手先 |
|---|---|---|
| 株価（日足・分割調整済み、上場廃止銘柄を含む） | エントリー・出口・時価総額 | 手元の SQLite |
| TOPIX（始値・終値） | 超過リターンの基準 | DB 内の指数データ、または 1306（TOPIX 連動 ETF）で代用 |
| 過去の開示一覧（日時・コード・タイトル） | イベント | J-Quants TDnet アドオンの一括ダウンロード（CSV） |
| 発行済株式数（または時価総額） | 時価総額帯 | DB にあればそれを使う。なければ J-Quants の財務データ |

## 使い方

```bash
pip install -e ".[dev]"

# 1) DB の構造を調べる（メタ情報だけを表示）
python scripts/inspect_db.py /path/to/stock.db

# 2) 設定を作る（テーブル名・列名を 1) の結果に合わせる）
cp config/example.toml config/local.toml

# 3) Phase 1（学習期間だけを集計して表示）
python scripts/phase1.py --config config/local.toml

# テスト
pytest
```

出力は集計値だけ。イベント単位の明細は `output/`（git 管理外）に保存する。

## 方法

### イベント
タイトルに次のキーワードを含む開示（NFKC 正規化して照合、表記揺れを含む）:
事業撤退／事業譲渡／店舗閉鎖（閉店）／子会社の解散（清算）／特別損失／減損／構造改革／価格改定（値上げ・料金改定）。
訂正・経過開示・清算結了・中止/延期の開示は除外。定義は `tdnet_edge/keywords.py`。

### エントリー（先読みなし）
「開示後に初めて約定できる価格」を日足で近似する（`tdnet_edge/timing.py`）。

| 開示時刻 | エントリー | 開示前の終値（反応・時価総額の基準） |
|---|---|---|
| 寄付前（〜8:59） | 当日始値 | 前営業日終値 |
| 立会中・昼休み（9:00〜大引け前） | 当日終値 | 前営業日終値 |
| 大引け以降・休日・時刻不明 | 翌営業日始値 | 当日（直近営業日）終値 |

- 大引けは 2024-11-05 から 15:00 → 15:30。15:00 の開示は、それより前なら引け後、以後は立会中として扱う
- 売買が成立しなければ、その後最初に約定した日の始値（最大5営業日）
- 感応度分析として「20時スキャン → 翌営業日寄付」（Phase 3 の運用と同じ条件）も併記

### 超過リターン
エントリー価格から h 営業日後の終値までの買い持ちリターン − 同期間の TOPIX リターン（h = 20/60/120/250）。
- 途中で上場廃止: 最後の約定値で売却し、残り期間は TOPIX で運用したとみなす（生存バイアス対策）
- 出口日がデータ範囲外: 未確定として集計から外す
- 同じ銘柄・同じエントリー時点の開示は1件に統合。同一銘柄の後続イベントは20営業日間引く（キーワード別は銘柄×キーワードごと）

### 切り口
キーワード別／時価総額帯別（〜100億・100〜300億・300〜1000億、参考に1000億超）／開示直後の反応別（開示前の終値 → エントリー価格が上げたか下げたか）／年別。

### 検証期間（ホールドアウト）
- 直近1年の開示は検証用に取り置き、Phase 1・2 では使わない。開始日は初回実行時に `state/holdout.json` に固定
- 株価も検証期間の前日までしか読み込まない
- 学習期間のイベントでも、出口日が検証期間に入る保有期間は除外する（パージ）
- 検証期間の評価はルールを確定した後に1回だけ行う

### t値
同時期のイベントは相関し、長い保有期間ほど互いに重なる。イベントを独立とみなす t値は過大になるため、
カレンダータイム・ポートフォリオ法（毎営業日、保有中のイベントを等ウェイトで持った場合の日次超過リターンの t値、Newey-West 補正）を使う。

## 制約・注意
- 日足しかないため、立会中の開示は「当日終値」で近似（開示後に約定がなかった場合は開示前の価格になりうる）
- ストップ安での買いは比例配分で全量約定しない可能性がある（考慮していない）
- 売買コスト（小型株はスプレッドが広い）は未控除
- J-Quants のデータは再配布不可（個人利用限定）。データ・明細は git にコミットしない
- `tdnet` ライブラリ（Phase 3 で使用予定）は AGPL v3
